## The Challenge

When an organization decides to adopt AI, picking a model is the easy part. The hard part is deploying it so that product designers, marketers, and engineers all get real value, with different needs, data access requirements, and risk tolerances, while meeting the security posture a financial services company demands.

This is an internal platform: its users are employees, not customers. The bar was still high, because the data around it is regulated.

## The Approach

### Architecture: MCP as the Integration Layer

We used the Model Context Protocol (MCP) as the integration backbone. It gave us a standard way to connect Claude to internal tools and data without building bespoke integrations for every team.

- **Domain-scoped servers, composed per team**: servers are organized by domain (analytics, content, engineering tools), and each team's configuration is assembled from the pieces it is approved to use
- **API connectors as the boundary**: Claude reaches internal systems through authenticated APIs, not direct database access
- **Plugin architecture**: team-specific plugins carry each group's prompts, tool subsets, and output formats

### Governance: RBAC and an Agent Registry

- **Role-scoped permissions**: each team can only reach the servers and tools approved for its role
- **Agent registry**: a central record of agents and connectors, built with governance partners
- **Auditability**: AI interactions are logged so that usage can be reviewed
- **Data boundaries**: sensitive data is handled through explicit allow-lists
- **Human approval**: higher-risk actions are gated

### Per-Team Customization

Each of the product, design, marketing, and engineering teams got a plugin shaped around its own workflow: its own prompts, tool subset, and output format, rather than a generic assistant.

## Patterns That Emerged

1. **Start with the workflow, not the technology.** The best AI tools solve real friction, not hypothetical problems.
2. **Security as a feature, not a gate.** Making access rules easy to understand made teams trust the system and adopt it faster.
3. **Servers compose.** Once the core connectors existed, new team configurations were fast to assemble.
4. **Governance scales better than freedom.** Scoped access meant fewer surprises and more trust from leadership.

## Outcome and Scope

- Rolled out company-wide, with team-specific plugins and MCP integrations for product, design, marketing, and engineering
- An agent registry and governance model around agents and connectors
- A reusable architecture in which new team configurations reuse existing connectors

I would not describe this as a shipped customer-facing AI product, and I do not present it as one. It is enterprise platform leadership, supported by hands-on prototyping. The next layer I would put in place is per-team adoption and time-saved measurement, plus evaluations on the highest-risk workflows.
